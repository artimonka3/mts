# Backup / restore MVP

1. Для согласованного снимка остановить `api` и `worker`; выполнить `python3 scripts/database_backup.py backup --output .local/backups/mvp.dump`, отдельно архивировать уже зашифрованную `.local/audio`, затем запустить сервисы. Dump имеет права 0600; backup хранить на зашифрованном носителе вне репозитория.
2. Ключи `MTS_DATA_ENCRYPTION_KEY` и `MTS_AUDIO_ENCRYPTION_KEY` хранить отдельно от архивов. Без исходных ключей восстановленные записи прочитать нельзя. `.env` никогда не включать в dump/audio archive; сроки жизни backup должны соответствовать политике удаления.
3. Проверка восстановления: `python3 scripts/database_backup.py restore --input .local/backups/mvp.dump --database mts_restore_test`. Команда отказывается писать в настроенную рабочую БД, системную БД или непустую БД. Audio восстанавливать отдельно в пустую папку, проверить записи с исходными ключами; переключение приложения на новую БД — отдельное осознанное действие. Для обычного named volume добавить `--named-volume` перед subcommand.

Шифрование полей не скрывает всю структуру БД: идентификаторы, состояния и timestamps
доступны администратору. Поэтому диск, backup-носитель и доступ к ключам также защищаются.
Согласованный архив БД+audio требует остановки записи. Прототип не управляет KMS,
ротацией ключей и автоматическим удалением внешних архивов.
