# Этап 9 — задачи и настройки

**Сделано:** tasks — те же принятые Agreement; owner-only фильтры по клиенту,
сроку, состоянию, приоритету, тегам, поиску action/title и demo. Сортировка,
пагинация, календарь с отдельным списком unknown. Выполнение, отмена и возврат
проверяют version и Idempotency-Key. CRUD тегов/шаблонов/триггеров сохраняет
immutable revisions; analysis получает snapshot. Preview триггеров — буквальный
поиск фраз с Unicode offsets, без семантических обещаний.

**Маленькая проверка:** общий набор stages 9–11: 16 focused tests; отдельно
проверены date-only overdue, state transitions, replay/conflict/reopen, immutable
settings snapshot. Ruff проходит. HTTP сценарий проверяется сквозным демо.

**Проблема → решение:** date-only нельзя фильтровать по следующей полуночи;
для календаря используется начало даты, для overdue — конец указанного дня.
Удаление тега убирает только live ссылки; история остаётся immutable.

**Приёмка:** accepted виден в tasks; proposed не виден; stale version →409;
повтор выполнения не повышает version; срок без времени не просрочен утром.

**Оценка:** нормально для небольшого MVP. Расшифрованные JSON фильтруются после
owner-scoped SQL, поэтому большие выборки потребуют индексов/проекций. Триггеры
пока конфигурация и буквальный preview; результат LLM не измерен.
