# Этап 8 — договорённости и подтверждение

**Статус: готово для MVP.** Создание/исправление предложений, accept/reject/unconfirm,
история, evidence, отдельные verification/execution. У принятой договорённости
правки требуют `confirm_changes`; каждый переход требует актуальную version.
Accept/reject/unconfirm поддерживают повтор по `Idempotency-Key`.

**Малые проверки:** 9 unit-проверок общего result-набора прошли (включая Unicode emoji,
неверный offset срока и запрет выдуманного времени у unknown). PostgreSQL-тест:
accept и replay совпадают; неподтверждённая правка принятой задачи отклонена;
сохранены 3 неизменяемые ревизии; старое evidence помечено на перепроверку;
истёкшая quote не выдаётся. Общий интеграционный тест прошёл.

**Проблемы → решение:** quote проверяется точным Unicode slice; participant/tag
принадлежат владельцу и звонку; история и replay тоже скрывают истёкшие quotes.
Условие требует явного resolution перед accept; unknown due сохраняется без
искусственного дедлайна. Эффекты напоминаний и CRM создаются атомарно в транзакции.

**Приёмка:** чужой UUID не открывает ресурс; stale version даёт 409; ручная оценка
не заменяет исходную confidence. Точность модели не измерена. История/результат
готовы к полному HTTP smoke, который выполняется при сборке остальных этапов.
