# Границы текущего MVP

- Настоящие ASR, LLM и диаризация отключены. Заглушка не анализирует произвольную
  речь: allowlisted demo берёт синтетический development fixture. Изменённый demo
  transcript не получает прежний результат как якобы новый анализ.
- 24 диалога — синтетические, authored fixtures; независимая человеческая проверка
  ожидается. Нет реального аудио holdout и нет измеренного ≥90%. CLI evaluation
  сравнивает только явно переданные predictions; extraction и keywords считаются
  отдельно, ASR остаётся not_measured.
- Frontend React, запись звонков телефоном, операторская IMS/конференция, роли
  руководителя и доступ команды, реальные CRM, SMS/email/push — следующие работы.
  В MVP права остаются owner-only даже для пользователей общей организации.
- Триггеры — настройки плюс буквальный preview. Семантическое понимание условий,
  переносов/отмен между разными звонками и произвольных дат зависит от будущего
  провайдера. Date helper понимает только ограниченные явные выражения; неизвестные
  или неоднозначные даты требует уточнить.
- Task export/filter для небольшого demo работает по расшифрованной owner-scoped
  выборке. Для большого объёма нужны проекции/индексы и нагрузочная проверка.
- Файловый ICS не является синхронизацией: скачанные копии нельзя отозвать. Данные
  mock CRM имеют replay/version/tombstone; настоящих внешних коммуникаций нет.
- Напоминания сохраняются в БД, без browser push. Policy offsets относятся к
  явно выбранному date-only reminder base time; новая политика полностью
  применяется при следующем изменении Agreement. Quiet hours/enabled проверяются
  также непосредственно перед отправкой внутреннего уведомления.
- Фернет шифрует private text/JSON/audio; operational metadata остаётся queryable.
  Это не шифрование всего диска/резервных копий. Ключи лежат только в process config
  и `.env`; резервируйте их отдельно. Автоматическое восстановление потерянного
  ключа отсутствует. Миграция защищённого формата требует действующий ключ.
- Локальный HTTP допускает insecure session cookie только development. Перед
  публикацией нужны HTTPS, Secure cookies, закрытые credentials, резервирование,
  политика ключей и эксплуатационная проверка. Юридические нормы РБ и операторская
  запись требуют отдельной актуальной проверки; здесь правовое заключение не дано.
- Идентификаторы/версии и audit сохраняются как метаданные; retention удаляет private
  source/copied text. Уже скачанные пользователем файлы не управляются backend.
  Тесты проверяют основной сценарий, а не длительную эксплуатацию/HA/нагрузку.
