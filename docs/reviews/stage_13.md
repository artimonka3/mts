# Этап 13 — сквозной MVP и хранение

**Сделано:** все backend-этапы 3–12 соединены; модели по-прежнему отключены.
Чувствительные тексты/JSON в PostgreSQL и аудиофайлы шифруются Fernet с внешними
ключами. Истечение источников очищает все версии текста, summary, цитаты и копии
в идемпотентных ответах. Принятые бизнес-записи имеют отдельный срок хранения.
Полное удаление прекращает jobs/напоминания и закрывает запись в mock CRM навсегда.
Есть короткий демо-сценарий, actual OpenAPI и команды backup/restore.

**Проблемы → решения:**
- Docker-диск заполнен: удалён неиспользуемый воспроизводимый build cache,
  освобождено 7,138 ГБ; затем образ с FFmpeg собран. Пользовательские volumes,
  контейнеры и образы сохранены. PostgreSQL продолжает работать через host-storage.
- Общий тест выявил отсутствие is_demo в provenance и неверную проверку folded
  ICS-строки: provenance дополнен, календарный тест проверяет unfolded текст.
- Старый lease мог сохранить поздний результат, а отмена имела обратный порядок
  блокировок: общий порядок Call → Job, финальная проверка токена и срока lease.
- Повтор webhook мог вернуть удалённую запись: постоянный terminal tombstone;
  локальный mock receiver получает его в транзакции удаления.
- Chunked multipart превышение ловилось parser как 400: теперь HTTP 413.

**Маленькая проверка:** сквозной API-тест проходит от двух пользователей до
подтверждения/экспорта/выполнения/дашборда/удаления. Отдельные тесты проверяют
retention, ciphertext, подмену шифротекста, ограничения body и отсутствие
воскрешения удалённых данных. Backup создан для тестовой БД и успешно восстановлен
в пустую mts_mvp_restore_test; повторное восстановление в непустую БД отклонено.
Точные результаты финального прогона и Docker smoke записаны в MVP_STATUS.md.

**Приёмка:** make up-host + make seed-host; вход demo/demo2; создание syn_01;
подтверждение с CSRF/Idempotency-Key; accepted появляется в tasks; экспорт;
CRM delivery; перенос/выполнение меняют напоминания и метрики; чужие ID недоступны;
удаление не оставляет источники и не допускает позднее восстановление.

**Оценка:** пригодно для демонстрации backend MVP. Это быстрый первый проход,
которому ещё нужно общее ревью перед реальным развёртыванием. Настоящие ASR,
diarization, LLM, VAD, внешние CRM/календари, роли руководителя, frontend,
юридическая проверка и подтверждение ≥90% остаются отдельными работами.
Ротация ключей/KMS и автоматическое вытеснение внешних backup пока отсутствуют;
согласованный backup требует остановки записывающих сервисов.
